Why a prompt

Language models know an older, smaller version of this library — or guess at one. Paste the prompt below at the start of a conversation (or add it to your editor's rules file) and the model writes code against the real API: correct option names, the security defaults, the auth bodies, and the mistakes to avoid.

# Cursor
mkdir -p .cursor/rules && curl -fsSL https://ornate-source.github.io/controllerSets/llms-full.txt \
  -o .cursor/rules/controller-sets.md

# GitHub Copilot
mkdir -p .github && curl -fsSL https://ornate-source.github.io/controllerSets/llms-full.txt \
  -o .github/copilot-instructions.md

Already have a rules file? Append instead of overwriting: replace -o FILE with >> FILE.

Prompts that work well

After the guide, ask in plain language. Say what the data is, who may read it and who may change it — the model turns that into allowlists and guards.

Build an Express API for a blog with express-controller-sets:
- Post { title, body, tags[], author (ref User), published }
- Anyone can list and read published posts, search title and body, filter by tag, newest first
- Only signed-in users can create posts; author is set from the token, never the body
- Only admins can delete
- Email + password auth with refresh tokens (rotation on), password reset by email via SMTP
Give me the models, app.js and a .env.example.
Add S3 image uploads to my Product router: one "cover" image and up to 6 "gallery" images,
JPEG/PNG/WebP only, 5 MB each, compressed at "medium". Keep writes admin-only.
Review this file against the express-controller-sets guide. List every place where a client
could write a field it shouldn't, read another user's data, or reach an unguarded route.

Check what it wrote

Models are fluent, not infallible. Before running generated code, check these five things — they are where mistakes cost the most:

  1. Every router has allowedFields (or blockedFields) — and it does not include server-owned fields like role or ownerId.
  2. Every write route has a guard in middlewares. allowedFields: [] alone does not stop DELETE.
  3. errorHandler is mounted last and express.json() first.
  4. Secrets come from the environment — token.secret is at least 32 characters and never in the code.
  5. Only real options are used. Anything not in createRouter is invented — at best ignored, at worst a false sense of safety.
