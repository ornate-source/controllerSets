  model: User,                                       // add googleId: String to the schema
  token: { secret: process.env.JWT_SECRET },
  social: { google: { clientId: process.env.GOOGLE_CLIENT_ID } },
});

Providers, and adding your own

Each provider is verified with the provider. A profile the client sends is a claim about who someone is, and none of these take one on trust.

Provider Send How it is checked
Google { idToken } RS256 signature against Google's published keys, then issuer and audience.
Apple { idToken, name? } The same, against Apple's keys. Apple sends a name only on first authorization, so the client forwards it.
Facebook { accessToken } debug_token confirms the token was minted for your app, then the profile is read.
GitHub { accessToken } or { code } A code is exchanged server-side, so the client never holds the secret. The verified primary email is fetched separately.

A provider only exists once you have configured it — an unconfigured one is a 404, not an open door. Sign-in matches on the provider's account id first, and falls back to a verified email so a social login links to the account that already registered by password.

Any other provider. A provider is one function. Supply verify and it replaces the built-in entirely:

social: {
  discord: {
    idField: 'discordId',
    verify: async ({ accessToken }) => {
      const profile = await fetchDiscordUser(accessToken);
      return { id: profile.id, email: profile.verified ? profile.email : null };
    },
  },
}
