ControllerSets

Express Controller Sets

An advanced, unified toolkit for Express.js that accelerates API development by providing automated CRUD operations, dynamic routing capabilities, and robust Amazon S3 file upload handling out of the box.

Node 20+ Mongoose 9+ Express 5+ Multer 2+

Designed to help you build production-ready APIs faster by automating repetitive controller logic and complex S3 middleware configuration while maintaining type safety and maximum flexibility.

Installation

Install the package using your favorite package manager:

npm install express-controller-sets mongoose express

Only if you use the S3 upload routes, also install the upload peers:

npm install multer @aws-sdk/client-s3

Security Model

This package generates public HTTP endpoints over your Mongoose models. Two things are deliberately not handled for you, and both will leave your API exposed if you skip them.

1. Authentication is yours to supply

Every generated route is open until you pass middleware. There is no implicit auth.

createRouter({
    model: Order,
    middlewares: [requireAuth, requireRole('staff')],
});

2. Declare what clients may write and filter

Without allowedFields, every field your schema defines is writable through POST and PATCH — including role, isAdmin, or balance. Mongoose's strict mode does not protect you here: it discards keys your schema does not define, which means it drops typos and faithfully saves the privilege escalation.

createRouter({
    model: User,
    allowedFields: ['name', 'email', 'avatar'],   // writable by clients
    blockedFields: ['role'],                      // or subtract instead
    filterableFields: ['createdAt'],              // ?compareField= / ?rangeField=
    sortableFields: ['createdAt'],                // ?sort=
});

Fields not named in filterableFields / sortableFields return 400. This matters because a filterable field is readable even when it is excluded from the response: a client can binary-search a password hash or reset token from the result counts alone.

Defaults since 3.0: search terms are regex-escaped, unpaginated reads are capped at 100 documents, uploads are stored with a private ACL and a content type derived from the file's bytes rather than the client's header, and 5xx responses no longer echo internal error messages. See MIGRATION.md to upgrade from 2.x.

Global Error Handling

To ensure all errors (including database validation failures) are returned in professional JSON format, use the built-in errorHandler middleware.

import express from 'express';
import { createRouter, errorHandler } from 'express-controller-sets';

const app = express();
app.use(express.json());

// ... your routes ...

// MUST BE ADDED LAST: Global JSON Error Handler
app.use(errorHandler);

Standardized Error Response

All errors caught by this middleware return a consistent body:

{
    "success": false,
    "error": "Validation Error: name is required",
    "requestId": "3f9c1e64-...",
    "stack": "... (only visible in development) ..."
}

Client-facing messages are deliberate. Validation, cast, duplicate-key and upload errors return a specific message. Anything else returns a generic "Internal Server Error" — driver and SDK messages routinely contain connection strings, hostnames and bucket names. Use the requestId to find the full error in your server logs.

Quick Start

Build a full-featured API for your model in just a few lines of code.

import express from 'express';
import { createRouter, errorHandler } from 'express-controller-sets';
import Product from './models/Product.js';

const app = express();
app.use(express.json());

// Create all CRUD routes automatically
const productRouter = createRouter({
    model: Product,
    orderBy: '-createdAt',              // Sort by newest
    search: ['name', 'category.name'],  // ?search= / ?s=, including relational fields
    query: ['category'],                // Enable ?category= filtering

    // Fields a client may write. Without this, every field your schema
    // defines is writable through POST and PATCH.
    allowedFields: ['name', 'price', 'category', 'description'],

    // Fields usable with ?compareField= / ?rangeField= and ?sort=
    filterableFields: ['price', 'category'],
    sortableFields: ['price', 'createdAt'],
});

app.use('/api/products', productRouter);
app.use(errorHandler);

Controller Sets

The ControllerSets class provides the core logic for handling Mongoose operations. You can use it directly for custom route handling by instantiating it with specific options.

Constructor Parameters

Parameter Type Description
model Mongoose Model Required. The Mongoose model that the controller will operate on (e.g., Product, User).
orderBy String The default sorting behavior when fetching lists (e.g., '-createdAt' for newest first). Defaults to 'none'.
query Array<String> An array of field names that are allowed to be filtered directly via query parameters (e.g., ['category', 'status'] allows ?status=active).
search Array<String> | String Fields to include when a user provides the ?search= or ?s= query parameter. Supports relational dot notation (e.g., 'category.name').
runAfterCreate Function An optional asynchronous callback function executed immediately after a new document is created. It receives the newly created document as its argument.
onGet Function An optional hook (req, res) that returns { populates, selects } to conditionally modify how data is populated or selected on all GET operations.
allowedFields Array<String> | Object Security. Fields a client may write via POST/PATCH. Accepts a flat array, or { create, update } for per-verb control. If omitted, every field your schema defines is writable.
blockedFields Array<String> | Object Security. Fields a client may never write. Applied after allowedFields. _id, __v, createdAt and updatedAt are always blocked.
filterableFields Array<String> Security. Fields usable with ?compareField= and ?rangeField=. Defaults to query. Anything else returns 400.
sortableFields Array<String> Security. Fields usable with ?sort=. Defaults to query plus the orderBy field.
maxLimit Number Hard cap on documents returned, paginated or not. Defaults to 100.
allowRawRegex Boolean Pass search terms to MongoDB unescaped. Unsafe for untrusted callers — a crafted pattern can stall the database. Defaults to false.
maxSearchLength Number Maximum accepted length of a search term. Defaults to 128.
lean Boolean Return plain objects, bypassing schema toJSON transforms. Faster, but any field you strip in a transform will reappear. Defaults to false.
strictAfterCreate Boolean Propagate runAfterCreate failures instead of logging and swallowing them. Defaults to false.
legacyMode Boolean Restores 2.x behaviour: no field gating, raw regex, unbounded reads. A migration bridge only — it re-enables known vulnerabilities.
logger Object Custom logger exposing warn / error / debug. Defaults to the console. 
import { ControllerSets } from 'express-controller-sets';
import Product from '../models/Product.js';

const productController = new ControllerSets({
    model: Product,
    orderBy: '-createdAt',
    query: ['category'],                     // ?category= equality filtering
    search: ['name', 'tags'],                // ?search= / ?s=
    allowedFields: ['name', 'tags', 'price', 'category'],
    filterableFields: ['price', 'category'],
    sortableFields: ['price', 'createdAt'],
    runAfterCreate: async (doc) => {},
    onGet: (req, res) => ({ selects: '-hiddenField' }),
});

// Use in manual routes
router.get('/', productController.getAll);
router.post('/', productController.create);
router.get('/:id', productController.getById);
router.patch('/:id', productController.update);
router.delete('/:id', productController.delete);

S3 File Upload Middleware

Handle file uploads to S3-compatible storage with ease. The middleware automatically updates req.body with S3 locations.

Type: This is a specialized Express middleware wrapper around Multer and the AWS SDK. It intercepts multipart form data, optionally compresses images using Sharp, securely uploads them directly to S3 via memory buffers, and seamlessly forwards execution back to your route handler.

Middleware Arguments

Argument Type Description
req Object The standard Express Request object.
res Object The standard Express Response object.
next Function The standard Express Next callback.
options Object Upload configuration. See the table below.

Upload Options

Option Type Description
uploadPath String Destination folder inside your bucket. Defaults to 'files/'.
fields Array Multer field configuration, e.g. [{ name: 'avatar', maxCount: 1 }]. Add formatToUrlObject: true to store { url } instead of a bare string.
acl String Security. Object ACL. Defaults to 'private'. Pass 'public-read' only when the objects are genuinely public.
allowedMimeTypes Array<String> Security. Types accepted after sniffing the file's bytes. Defaults to common images plus PDF.
maxFileSize Number Per-file limit in bytes. Defaults to 10 MB.
maxFiles Number Maximum files per request. Defaults to 10.
imgOptimizations String Compression level ('low', 'medium', 'high'). Server-side only by default.
allowClientImageOptions Boolean Let clients pick the level via ?imgOptimizations=. Each level costs CPU, so an open endpoint is an amplification vector. Defaults to false. 
import { fileUploadMiddleware } from 'express-controller-sets';

router.post('/upload', (req, res, next) => {
    fileUploadMiddleware(req, res, next, {
        uploadPath: 'uploads/',
        fields: [{ name: 'avatar', maxCount: 1 }],
        allowedMimeTypes: ['image/jpeg', 'image/png', 'image/webp'],
        acl: 'public-read',        // avatars are genuinely public
        maxFileSize: 5 * 1024 * 1024,
        imgOptimizations: 'medium',
    });
}, (req, res) => {
    res.json({ url: req.body.avatar });
});

The client's Content-Type is never trusted. Since 3.0 the stored content type and file extension are derived from the file's actual bytes. Uploading HTML or SVG labelled image/png is rejected rather than stored and served as executable content on your bucket's origin. Types outside a strict inline allowlist are stored with Content-Disposition: attachment.

Private objects are not fetchable from the returned URL. Serve them through presigned URLs or a CDN origin-access identity — file.key is populated alongside file.location for exactly this purpose.

Image Compression & Optimization

Drastically reduce your S3 storage costs and improve API response times by automatically optimizing uploaded images via the imgOptimizations feature. Powered by Sharp, the module utilizes a highly efficient, multi-pass binary search algorithm to dynamically scale down the file size while preserving original image dimensions and visual fidelity.

Available Compression Profiles:

Level Target File Size Best Used For
low 75% - 80% of original size High-fidelity images where maximum quality is prioritized over bandwidth savings.
medium / med 60% - 65% of original size General purpose uploads (e.g., product photos, hero images) offering the perfect balance of quality and size.
high 40% - 45% of original size Avatars, thumbnails, and heavy traffic endpoints where aggressive bandwidth savings are crucial.

You can seamlessly integrate image optimization into your workflow in two ways:

1. Route-Level Setup (Static Default)

Specify the default compression level when initializing your router:

import { createRouterS3upload } from 'express-controller-sets';

const router = createRouterS3upload({
    model: User,
    path: 'avatars/',
    fields: [{ name: 'avatar', maxCount: 1 }],
    imgOptimizations: 'medium' // All avatars will be compressed to 60-65% size by default
});

2. Client-Controlled (Opt-In)

Changed in 3.0. Client-supplied optimization levels are now ignored by default. Each level runs up to seven sequential re-encodes of a multi-megabyte buffer, so an endpoint where anyone can request high is a CPU-amplification vector. Your server-side setting always wins unless you opt in.

To accept a per-request level, enable it explicitly. Values are still allowlisted, so an unrecognised level falls back to your configured default:

createRouterS3upload({
    model: User,
    path: 'avatars/',
    imgOptimizations: 'medium',                     // server default
    upload: { allowClientImageOptions: true },      // allow per-request override
});

// Client may now request a level via query string or the
// x-img-optimizations header:
fetch('/api/users?imgOptimizations=high', { method: 'POST', body: formData });

3. Skipping Optimization

Omit imgOptimizations entirely and files upload untouched. Formats that cannot be safely re-encoded — GIF, SVG, AVIF, HEIC — always pass through unchanged, even when a level is configured.

Fixed in 3.0: these formats previously fell through to the JPEG encoder, producing JPEG bytes stored under a .gif key with Content-Type: image/gif. Animation was lost and the stored object was corrupt. Extensions are now derived from the bytes actually written.

Dynamic Routers

Accelerate your API development by utilizing our dynamic routing helper functions. With a single function call, you can instantly scaffold full-featured Express routers equipped with comprehensive CRUD operations, integrated S3 file uploads, and advanced querying capabilities out-of-the-box.

Basic Router

import { createRouter } from 'express-controller-sets';
import Product from './models/Product.js';

const router = createRouter({
    model: Product,
    orderBy: '-createdAt',              // Sort order for GET requests
    query: ['category', 'status'],      // Allowed query parameters for filtering
    search: ['name', 'description'],    // Fields to search when ?search=term is used
    runAfterCreate: async (doc) => {},  // Hook executed after document creation
    onGet: (req, res) => { return {} }, // Hook to conditionally apply populate/select
    middlewares: [authMiddleware],      // Array of middlewares to run before controllers

    allowedFields: ['name', 'description', 'price', 'category'], // Client-writable
    filterableFields: ['price', 'category'],  // ?compareField= / ?rangeField=
    sortableFields: ['price', 'createdAt'],   // ?sort=
    maxLimit: 100,                            // Cap on documents per response
});

Router with S3 File Upload

Automatically combines CRUD logic with S3 file upload middleware.

import { createRouterS3upload } from 'express-controller-sets';
import User from './models/User.js';

const router = createRouterS3upload({
    model: User,
    orderBy: '-createdAt',              // Sort order
    query: ['role'],                    // Allowed query params
    search: ['username', 'email'],      // Searchable fields
    runAfterCreate: async (doc) => {},  // Post-create hook
    onGet: (req, res) => { return {} }, // Conditional populate/select
    middlewares: [authMiddleware],      // Route middlewares

    allowedFields: ['username', 'email', 'avatar'], // Client-writable fields
    sortableFields: ['createdAt'],                  // ?sort= allowlist

    path: 'avatars/',                              // S3 folder path
    fields: [{ name: 'avatar', maxCount: 1 }],     // Multer upload fields
    imgOptimizations: 'medium',                    // Compression default
    upload: {
        acl: 'public-read',                        // Avatars are public
        allowedMimeTypes: ['image/jpeg', 'image/png', 'image/webp'],
    },
});

Registering the Router

Because the helper functions return a standard Express router, you register them in your main application exactly as you would normally:

import express from 'express';
// import productRouter from './routes/productRouter.js'

const app = express();

app.use(express.json());
app.use('/api/products', productRouter);

Conditional Populate (onGet)

The onGet hook gives you request-time control over .populate() and .select() for all GET operations (getAll, getById, and paginated results). It is entirely optional — without it, ControllerSets works exactly as before.

Hook Signature

The hook receives (req, res) and returns an object with populates and/or selects:

onGet(req, res) {
    return {
        populates,  // string | object | array — passed to .populate()
        selects,    // string — passed to .select()
    };
}

Simple Demo

Use simple query parameters to conditionally include or exclude fields.

import { createRouter } from 'express-controller-sets';
import Product from './models/Product.js';

const productRouter = createRouter({
    model: Product,
    query: ['category'],
    onGet: (req, res) => {
        // If ?noUsers=true is passed, exclude the 'users' field
        if (req.query.noUsers) {
            return { selects: "-users" };
        }
        // Otherwise, populate the users field
        return {
            populates: [{ path: "users.user", select: "name email" }]
        };
    }
});

Complex Demo

Chain multiple populates and make decisions based on both query parameters and user roles.

const orderRouter = createRouter({
    model: Order,
    query: ['status'],
    onGet: (req, res) => {
        const populates = [{ path: "customer", select: "name email" }];
        let selects = "";

        // Add detailed item data if requested
        if (req.query.detailed === "true") {
            populates.push({ path: "items.product", select: "name price image" });
        } else {
            selects = "-items";
        }

        // Only admins can see who the order is assigned to
        if (req.user?.role === "admin") {
            populates.push({ path: "assignedTo" });
        }

        return { populates, selects };
    }
});

Advanced Demo (Modular Reuse)

Extract your onGet logic into isolated, reusable hook functions to share complex population logic across multiple resource routers.

// hooks/populateUsers.js
export const populateUsers = (req, res) => {
    if (req.query.noUsers) return { selects: "-users" };
    return { populates: [{ path: "users.user", select: "name email" }] };
};

// routes/products.js
import { populateUsers } from '../hooks/populateUsers.js';
const productRouter = createRouter({ model: Product, onGet: populateUsers });

// routes/orders.js — same hook, zero duplication
const orderRouter = createRouter({ model: Order, onGet: populateUsers });

First-Class TypeScript Support

Express Controller Sets is built with modern development in mind and ships with comprehensive TypeScript definitions out of the box. By passing your Mongoose document interfaces as generics, you unlock deep autocomplete, strict type-checking for hooks, and an enhanced developer experience.

End-to-End Type Safety

When you pass your interface (e.g., <IUser>) to the helpers, hooks like runAfterCreate automatically infer the correct document type, ensuring you never misspell a property.

import express from 'express';
import { createRouter, createRouterS3upload } from 'express-controller-sets';
import mongoose, { Document } from 'mongoose';

// 1. Define your Mongoose document interface
export interface IUser extends Document {
    name: string;
    email: string;
    age: number;
    avatar?: string;
}

// 2. Create the Mongoose schema and model
const userSchema = new mongoose.Schema({
    name: { type: String, required: true },
    email: { type: String, required: true },
    age: Number,
    avatar: String
});
const UserModel = mongoose.model<IUser>('User', userSchema);

// 3. Create a strongly-typed standard router
const standardRouter = createRouter<IUser>({
    model: UserModel,
    orderBy: '-age',
    search: ['name', 'email'],
    allowedFields: ['name', 'email', 'age'],
    sortableFields: ['age', 'createdAt'],
    // 'doc' is strictly typed as IUser
    runAfterCreate: async (doc) => {
        console.log(`New user created: ${doc.name} (${doc.email})`);
    }
});

// 4. Or create a strongly-typed S3 upload router
const avatarRouter = createRouterS3upload<IUser>({
    model: UserModel,
    path: 'avatars/',
    fields: [{ name: 'avatar', maxCount: 1 }],
    allowedFields: ['avatar'],
    imgOptimizations: 'medium',
    upload: {
        acl: 'public-read',
        allowedMimeTypes: ['image/jpeg', 'image/png', 'image/webp'],
    },
});

const app = express();
app.use('/api/users', standardRouter);
app.use('/api/avatars', avatarRouter);

API Reference

Option Type Description
model Mongoose Model The required Mongoose model that the controller will perform all CRUD operations against.
orderBy String The default sorting field (e.g., '-createdAt'). Clients may override it with ?sort=field, but only for fields listed in sortableFields.
query Array<String> Field names allowed for automatic equality filtering from the query string (e.g., ?status=active). Also serves as the default allowlist for ranges (?rangeField=price&range=10-50) and comparisons (?compareField=age&compareOperator=gte&compareValue=18) — override with filterableFields. Repeated params (?tag=a&tag=b) become an $in match.
search Array<String> | String Fields to execute regex searches against when ?s=term or ?search=term is provided. It dynamically builds a case-insensitive $or query. It fully supports relational dot-notation (e.g., category.name), automatically resolving the related IDs via an internal sub-query!
runAfterCreate async (doc) => void An asynchronous lifecycle hook triggered immediately after a new document is successfully created via POST. It receives the newly created Mongoose document (doc). Any errors thrown within this hook are caught and safely logged without breaking the API response.
middlewares Array<Function> An array of standard Express middlewares that will be applied to all routes generated by the router helper.
imgOptimizations String Optional default image optimization preset for S3 file uploads ('low', 'medium', or 'high').
onGet async (req, res) => Object An asynchronous hook executed right before querying the database on any GET request. It allows you to dynamically return an object containing { populates, selects } to apply conditional, request-time logic to Mongoose's .populate() and .select() methods.

Note on Pagination

Pagination is supported out-of-the-box for getAll queries. By appending ?page=1&pageSize=50, the response automatically provides a pagination metadata object alongside your results.

API Endpoints

All routers created with createRouter or createRouterS3upload follow standard RESTful patterns and include a powerful built-in filtering engine.

Method Endpoint Description
GET / List records with support for pagination, search, and custom filters.
POST / Create a new record. Supports multipart file uploads on S3 routers.
GET /:id Retrieve a single record by its 24-character hex ID.
PATCH /:id Update an existing record partially. Supports file updates on S3 routers.
DELETE /:id Permanently remove a record from the database.

Query Parameters (Filtering Engine)

The GET / endpoint supports several parameters out-of-the-box to filter and paginate your data.

Parameter Description Example
page The page number (starts at 1). ?page=2
pageSize Number of items per page. Defaults to 50, capped at maxLimit (100 by default). ?pageSize=50
search / s Global case-insensitive search across configured fields, including relational dot-notation. Terms are matched literally — regex metacharacters are escaped unless allowRawRegex is set. Capped at maxSearchLength (128) characters. ?s=laptop
sort Field to sort by, prefixed with - for descending. Must appear in sortableFields, otherwise returns 400. ?sort=-price
[fieldName] Direct equality filter for any configured query field. Repeat the parameter for an $in match. ?category=65a...
rangeField The numeric field to apply a range filter on, used with range. Must appear in filterableFields, otherwise returns 400. ?rangeField=price
range The range boundaries in format min-max. Supports min-only (min-) or max-only (-max) ranges. ?range=10-100
compareField The field to perform a dynamic comparison on. Must appear in filterableFields, otherwise returns 400. ?compareField=price
compareValue The target value to compare against. Tries to parse as a number if valid, otherwise treats as a string. ?compareValue=50
compareOperator The comparison operator: gt (>), gte (>=), lt (<), lte (<=), ne (!=), eq (==). Default is eq. ?compareOperator=gt

Usage Examples

1. Fetching Paginated & Sorted Results

// Fetch the second page of active products, sorted by price
fetch('/api/products?page=2&pageSize=20&sort=-price&status=active')
    .then(res => res.json())
    .then(data => {
        console.log(data.data); // Array of items
        console.log(data.pagination); // { total, page, pageSize, totalPage }
    });

2. Filtering by Numeric Range

Filter records dynamically by a numeric range using rangeField and range query parameters.

// Fetch products priced between $10 and $100
fetch('/api/products?rangeField=price&range=10-100')
    .then(res => res.json())
    .then(data => console.log(data.data));

// Fetch users aged 18 or older (min only)
fetch('/api/users?rangeField=age&range=18-')
    .then(res => res.json())
    .then(data => console.log(data.data));

3. Dynamic Field Comparison

Filter records dynamically on a field using comparison operators like greater than (gt), greater than or equal (gte), less than (lt), less than or equal (lte), not equal (ne), or equal (eq).

// Fetch products with price greater than 50
fetch('/api/products?compareField=price&compareValue=50&compareOperator=gt')
    .then(res => res.json())
    .then(data => console.log(data.data));

// Fetch active users with age less than or equal to 30
fetch('/api/users?status=active&compareField=age&compareValue=30&compareOperator=lte')
    .then(res => res.json())
    .then(data => console.log(data.data));

4. Global and Relational Search

Use ?s=term or ?search=term to execute a case-insensitive search across all fields configured in the router's search array. Because it natively supports dot-notation, you can even search inside populated references without writing complex aggregate queries.

// Assuming the router was created with search: ['name', 'description', 'category.name']
// This searches the Product's name/description AND the related Category's name!
fetch('/api/products?s=wireless')
    .then(res => res.json())
    .then(data => console.log(data.data));

5. Creating a Record with File Upload

When using createRouterS3upload, ensure you use FormData for multipart requests.

const formData = new FormData();
formData.append('name', 'New User');
formData.append('avatar', fileInput.files[0]);

fetch('/api/users', {
    method: 'POST',
    body: formData
    // Note: Don't set Content-Type header manually, 
    // fetch will set it for multipart/form-data with boundary automatically.
}).then(res => res.json());
