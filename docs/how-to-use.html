How to use

Put CRUD, auth, uploads and email together — plus ready-made answers to common tasks.

The building blocks#

A typical app uses four imports. Each step links to its own page.

  1. CRUD — one router per model

    app.use('/api/products', createRouter({
  model: Product,
  allowedFields: ['name', 'price'],     // what clients may write
}));

    CRUD →

  2. Auth — sign-up, login, and guards

    const auth = createAuthRouter({ model: User, token: { secret: process.env.JWT_SECRET } });
app.use('/api/auth', auth);

// Use its guards on any router
createRouter({ model: Order, middlewares: [auth.requireAuth], allowedFields: ['note'] });

    Auth →

  3. S3 Upload — files on a router

    app.use('/api/documents', createRouterS3upload({
  model: Document,
  fields: [{ name: 'file', maxCount: 1 }],
  allowedFields: ['title', 'file'],
}));

    S3 Upload →

  4. Email Sender — reset codes by mail

    createAuthRouter({
  // …
  mail: { transporter: nodemailer.createTransport(process.env.SMTP_URL), from: 'Acme <no-reply@acme.com>' },
});

    Email Sender →

  5. Configure with .env, and add the error handler last

    import 'dotenv/config';            // first line of your app
// … routers …
app.use(errorHandler);             // after every router

    .env examples →

All together#

A complete app.js with every feature. Delete what you don't need.

import 'dotenv/config';
import express from 'express';
import mongoose from 'mongoose';
import nodemailer from 'nodemailer';
import {
  createRouter, createRouterS3upload, createAuthRouter, errorHandler,
} from 'express-controller-sets';
import { User, Product, Document } from './models.js';

const app = express();
app.use(express.json());

// Auth: sign-up, login, refresh tokens, password reset by email
const auth = createAuthRouter({
  model: User,
  token: { secret: process.env.JWT_SECRET, expiresIn: '15m' },
  refresh: { enabled: true },
  mail: { transporter: nodemailer.createTransport(process.env.SMTP_URL), from: process.env.MAIL_FROM },
});
app.use('/api/auth', auth);

// CRUD: anyone reads products, admins change them
const products = { model: Product, query: ['category'], search: ['name'], orderBy: '-createdAt' };
app.use('/api/products', createRouter({ ...products, allowedFields: [] }));
app.use('/api/admin/products', createRouter({
  ...products,
  middlewares: [auth.requireAuth, auth.requireRole('admin')],
  allowedFields: ['name', 'price', 'category'],
}));

// Uploads: signed-in users attach files
app.use('/api/documents', createRouterS3upload({
  model: Document,
  middlewares: [auth.requireAuth],
  fields: [{ name: 'file', maxCount: 1 }],
  allowedFields: ['title', 'file'],
}));

app.use(errorHandler);

await mongoose.connect(process.env.MONGODB_URI);
app.listen(process.env.PORT ?? 3000);

Public, read-only

An empty allowedFields means no field is writable, so POST and PATCH are refused with a 400. Add a guard if you also want DELETE gone.

app.use('/api/articles', createRouter({
  model: Article,
  orderBy: '-publishedAt',
  query: ['category'],
  search: ['title', 'summary'],
  allowedFields: [],                         // nothing is writable
  middlewares: [(req, res, next) =>          // only reads get through
    ['GET', 'HEAD', 'QUERY'].includes(req.method) ? next() : res.status(405).end()],
}));
Two routers, one model

The most common shape: the public reads, staff edit. Each router carries its own allowlists, so the public one can never write — even if a guard is misconfigured.

const catalogue = {
  model: Product,
  orderBy: '-createdAt',
  query: ['category', 'isFeatured'],
  search: ['name', 'description'],
  filterableFields: ['price', 'category'],
  sortableFields: ['price', 'name', 'createdAt'],
};

// Anyone: read
app.use('/api/products', createRouter({ ...catalogue, allowedFields: [] }));

// Staff: read and write
app.use('/api/admin/products', createRouter({
  ...catalogue,
  middlewares: [auth.requireAuth, auth.requireRole('staff', 'admin')],
  allowedFields: ['name', 'price', 'description', 'category', 'isFeatured'],
}));
Server-owned fields

Fields like author, ownerId or tenantId come from the signed-in user, never from the body. Keep them out of allowedFields and set them in validate.create — whatever the client sent for them was already stripped.

app.use('/api/posts', createRouter({
  model: Post,
  middlewares: [auth.requireAuth],
  allowedFields: ['title', 'body', 'tags'],          // no 'author'
  validate: {
    create: (payload, { req }) => ({ ...payload, author: req.auth.userId }),
  },
}));
Only my records

Three pieces: force the owner into every list, check ownership on every /:id, and stamp the owner on create. Tested end to end — a user cannot list, read, change or delete another user's records, even by sending ?ownerId= themselves.

import express from 'express';
import mongoose from 'mongoose';
import { createRouter, HttpError } from 'express-controller-sets';

// 1. Lists: pin ownerId to the caller. Express 5 re-parses req.query on every
//    read, so assigning to it does nothing — shadow it with a real property.
const onlyMine = (req, res, next) => {
  Object.defineProperty(req, 'query', {
    value: { ...req.query, ownerId: String(req.auth.userId) },
    writable: true, configurable: true, enumerable: true,
  });
  next();
};

// 2. Single records: 404 unless the caller owns it (404, not 403 — don't
//    confirm that someone else's record exists).
const ownsNote = async (req, res, next) => {
  if (!mongoose.isValidObjectId(req.params.id)) return next();   // the controller answers 400
  const mine = await Note.exists({ _id: req.params.id, ownerId: req.auth.userId });
  if (!mine) throw new HttpError(404, 'Entry not found.');
  next();
};

const notes = express.Router();
notes.use(auth.requireAuth, onlyMine);
notes.use('/:id', ownsNote);
notes.use(createRouter({
  model: Note,
  orderBy: '-createdAt',
  query: ['ownerId'],
  enableQuery: false,                                  // QUERY filters from the body — keep it off here
  allowedFields: ['title', 'body'],
  validate: { create: (p, { req }) => ({ ...p, ownerId: req.auth.userId }) },   // 3. stamp the owner
}));

app.use('/api/notes', notes);

Don't skip step 2. The list filter only covers GET /. Without the /:id check, anyone who learns an id can read, edit or delete that record.

Populate & search a ref

onGet decides, per request, what to populate and select. Search can reach into a referenced model with a dotted path.

app.use('/api/books', createRouter({
  model: Book,                                  // author: { type: ObjectId, ref: 'Author' }
  search: ['title', 'author.name'],             // ?s=tolkien matches the author's name
  allowedFields: [],
  onGet: (req) => ({
    populates: [{ path: 'author', select: 'name avatar' }],
    selects: req.query.full ? '' : '-body',     // lists skip the heavy field
  }),
}));
Validate & normalise

Throw ValidationError with a field map and the client gets it back as fields. Return an object to replace the payload — that is how you trim, lowercase or derive values.

import { createRouter, ValidationError } from 'express-controller-sets';

const check = (p) => {
  const fields = {};
  if (p.price !== undefined && !(p.price >= 0)) fields.price = 'must be zero or more';
  if (p.sku !== undefined && !/^[A-Z0-9-]{4,20}$/.test(p.sku)) fields.sku = 'use 4–20 letters, digits or dashes';
  if (Object.keys(fields).length) throw new ValidationError('Check the submitted values.', fields);
  return p.name ? { ...p, name: p.name.trim() } : p;
};

createRouter({
  model: Product,
  allowedFields: { create: ['name', 'price', 'sku'], update: ['name', 'price'] },   // sku is set once
  validate: { create: check, update: check },
});
{ "success": false, "error": "Check the submitted values.",
  "fields": { "price": "must be zero or more" } }
Large collections

Offset pages get slower the deeper you go, and counting every match costs a full scan. Cursor pagination is one index seek per page at any depth. Index the sort field.

// Schema: eventSchema.index({ createdAt: -1 });

app.use('/api/events', createRouter({
  model: Event,
  orderBy: '-createdAt',
  pagination: 'cursor',       // follow pagination.nextCursor: ?cursor=…
  maxTimeMS: 2000,            // a slow query is cut off, not left running
  allowedFields: [],
}));

If you need page numbers but not totals, keep offset pagination and set countStrategy: 'none' — responses carry hasMore instead of totalPages.

Image uploads to S3

Install multer, @aws-sdk/client-s3 and (for compression) sharp, and set the S3 variables. Clients send multipart/form-data with the file fields named as below; the stored document gets the URLs.

import { createRouterS3upload } from 'express-controller-sets';

app.use('/api/admin/products', createRouterS3upload({
  model: Product,
  middlewares: [auth.requireAuth, auth.requireRole('admin')],
  path: 'products/',
  fields: [
    { name: 'cover', maxCount: 1 },
    { name: 'gallery', maxCount: 6 },
  ],
  imgOptimizations: 'medium',
  upload: {
    acl: 'public-read',                                 // product photos are meant to be seen
    allowedMimeTypes: ['image/jpeg', 'image/png', 'image/webp'],
    maxFileSize: 5 * 1024 * 1024,
  },
  allowedFields: ['name', 'price', 'cover', 'gallery'],
}));
curl -X POST localhost:3000/api/admin/products \
  -H "Authorization: Bearer $TOKEN" \
  -F name=Chair -F price=120 \
  -F cover=@cover.jpg -F gallery=@side.jpg -F gallery=@back.jpg
Complete auth

Email and password, short access tokens with rotating refresh tokens, password reset by email, and a welcome mail. Add the fields from What your model needs to your user schema.

import nodemailer from 'nodemailer';
import { createAuthRouter } from 'express-controller-sets';

const transporter = nodemailer.createTransport(process.env.SMTP_URL);

export const auth = createAuthRouter({
  model: User,
  identifiers: ['email'],
  token: { secret: process.env.JWT_SECRET, expiresIn: '15m' },
  refresh: { enabled: true, rotate: true, expiresIn: '30d' },
  roles: { list: ['user', 'admin'], default: 'user' },
  registerFields: ['name'],
  updateFields: ['name'],

  appName: 'Acme',
  mail: { transporter, from: 'Acme <no-reply@acme.com>' },

  onRegister: async (user) => {
    await transporter.sendMail({
      from: 'Acme <no-reply@acme.com>', to: user.email,
      subject: 'Welcome to Acme', text: `Hi ${user.name ?? 'there'}, thanks for signing up.`,
    });
  },
});

app.use('/api/auth', auth);

What a client does with it:

POST /api/auth/register      { "email": "ada@example.com", "password": "…", "name": "Ada" }
POST /api/auth/login         { "identifier": "ada@example.com", "password": "…" }
→ { "data": { "token": "…", "expiresIn": 900, "refreshToken": "…", "refreshExpiresIn": 2592000, "user": {…} } }

GET  /api/auth/me            Authorization: Bearer <token>
POST /api/auth/token/refresh { "refreshToken": "…" }       # when the access token expires
POST /api/auth/logout        { "refreshToken": "…" }
Rate-limit sign-in

Accounts lock after repeated failures, but that doesn't stop someone trying one password against many accounts. Put a limiter on the routes that get guessed at — it runs before the database is touched.

import rateLimit from 'express-rate-limit';

const tight = rateLimit({ windowMs: 15 * 60 * 1000, limit: 20 });

createAuthRouter({
  // …
  middlewares: { login: [tight], register: [tight], forgotPassword: [tight], resetPassword: [tight] },
});
Extra endpoints

A generated router is an ordinary Express router. Mount your own routes on the same path — before it, so they win.

const products = express.Router();

products.get('/stats', async (req, res) => {
  const [row] = await Product.aggregate([{ $group: { _id: null, avg: { $avg: '$price' }, n: { $sum: 1 } } }]);
  res.json({ success: true, data: row ?? { avg: 0, n: 0 } });
});

products.use(createRouter({ model: Product, allowedFields: [] }));

app.use('/api/products', products);    // GET /api/products/stats, plus the six generated routes

To reuse the generated behaviour under a different verb or path, call the handlers directly — see Custom routes.
