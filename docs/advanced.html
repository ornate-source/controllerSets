Advanced

Use each ControllerSets method — getAll, query, get, create, update, delete — on your own routes.

Use every method yourself#

createRouter is a thin layer over ControllerSets. Create the controller yourself and you can put each method on any route, with any middleware, next to your own code.

import { ControllerSets } from 'express-controller-sets';

const products = new ControllerSets({
  model: Product,                          // same options as createRouter
  query: ['category'],
  search: ['name'],
  allowedFields: ['name', 'price', 'category'],
});
MethodUsual routeReads from the requestResponds
getAllGET /req.query200 list (+ pagination)
queryQUERY /req.body (JSON)200 list (+ pagination)
getGET /:idreq.params.id200 record · 404
createPOST /req.body201 record
updatePATCH /:idreq.params.id, req.body200 updated record · 404
deleteDELETE /:idreq.params.id200 message · 404

Methods are pre-bound — pass them directly: router.get('/', products.getAll). Route parameters must be named :id.

getAll — list#

router.get('/', products.getAll);

Reads filters, search, sort and pagination from the query string — everything on API endpoints. Only fields allowed by query, filterableFields and sortableFields are accepted.

GET /products?category=chairs&s=oak&sort=-price&page=1&pageSize=20

query — list from a JSON body#

router.query('/', products.query);      // Node 22.2+ and Express 5

Same result as getAll, but reads { filter, search, sort, page, pageSize, limit, cursor } from the body. Needs express.json().

QUERY /products
Content-Type: application/json

{ "filter": { "price": { "gte": 50 } }, "sort": ["-price"], "page": 1 }

get — read one#

router.get('/:id', products.get);

Validates the id (400 if malformed), applies onGet, returns the record or 404.

create — insert#

router.post('/', products.create);

Keeps only allowedFields from req.body, runs validate.create, saves, runs runAfterCreate, responds 201. A duplicate unique key is a 409.

update — change fields#

router.patch('/:id', products.update);
router.put('/:id', products.update);       // want PUT? same handler

Applies only the fields sent ($set) after allowedFields and validate.update; responds with the updated record or 404.

delete — remove#

router.delete('/:id', products.delete);
{ "success": true, "message": "Item successfully deleted." }

A router by hand#

All six methods on your own router, with a different guard per route and an extra endpoint:

import express from 'express';
import { ControllerSets, errorHandler } from 'express-controller-sets';

const products = new ControllerSets({
  model: Product,
  query: ['category'],
  search: ['name'],
  sortableFields: ['price', 'createdAt'],
  allowedFields: ['name', 'price', 'category'],
});

const router = express.Router();
const admin = [auth.requireAuth, auth.requireRole('admin')];

router.get('/', products.getAll);                         // public
router.query('/', products.query);                        // public (Node 22.2+)
router.get('/featured', async (req, res) => {             // your own route — before '/:id'
  res.json({ success: true, data: await Product.find({ featured: true }).limit(10) });
});
router.get('/:id', products.get);                         // public
router.post('/', ...admin, products.create);              // admin only
router.patch('/:id', ...admin, products.update);
router.delete('/:id', ...admin, products.delete);

app.use('/api/products', router);
app.use(errorHandler);

Add logic around a method#

Run your own checks first, then hand over to the method:

// Only the owner may change or delete a note
const ownsNote = async (req, res, next) => {
  const note = await Note.exists({ _id: req.params.id, ownerId: req.auth.userId });
  if (!note) return res.status(404).json({ success: false, error: 'Entry not found.' });
  next();
};

router.patch('/:id', auth.requireAuth, ownsNote, notes.update);
router.delete('/:id', auth.requireAuth, ownsNote, notes.delete);

Methods send the response themselves. To change what a read returns, use onGet (populate / select) or your schema's toJSON.

Errors#

Methods answer client mistakes themselves (400, 404, 409) with { success: false, error }. Unexpected failures (a database outage) are thrown — mount errorHandler last so they become a clean 500.

HelperWhat it gives you
products.configThe resolved, frozen options.
products.getPopulates(req, res)What onGet resolves to for this request.
products.getPaginatedResults(req, res, filters, sort)One offset-paginated read of your own filter, sent as a standard paginated response.

How the handlers are put together

When the six generated endpoints aren't quite the shape you need.

Use the handlers on your own router#

Every controller method is a plain Express handler, so you can mount them individually — different middleware per verb, extra routes alongside, whatever you like.

import express from 'express';
import { ControllerSets } from 'express-controller-sets';
import Product from './models/Product.js';

const controller = new ControllerSets({
  model: Product,
  query: ['category'],
  allowedFields: ['name', 'price'],
});

const router = express.Router();

router.get('/',      controller.getAll);                    // public
router.query('/',    controller.query);                     // public, body-borne read
router.get('/:id',   controller.get);                       // public
router.post('/',     requireAuth, controller.create);       // staff only
router.patch('/:id', requireAuth, controller.update);
router.delete('/:id', requireAuth, requireAdmin, controller.delete);

// …and add whatever the generated set doesn't cover
router.get('/:id/related', myOwnHandler);

export default router;

router.query() only exists on runtimes that know the method. Wiring handlers yourself means guarding it yourself:

import { isQueryMethodSupported } from 'express-controller-sets';

if (isQueryMethodSupported()) router.query('/', controller.query);

How the handlers are put together#

Each handler is a short composition of the same four steps, and every step lives in its own module under src/core/. Reach for them when you are writing an endpoint this library does not generate — a rule enforced in one of these applies to anything built on it.

Module Responsibility
core/config.js Options in, one frozen config out. Every default is resolved once, here.
core/index.js The barrel everything outside core/ imports from — one import instead of nine. Modules inside core/ import each other directly, so the graph stays acyclic.
core/getAll.js · query.js · get.js · create.js · update.js · delete.js One module per route. The class itself is just the six methods.
core/list.js The retrieval getAll and query share — offset pages, keyset pages and plain lists.
core/cursor.js Keyset tokens: the tiebreaker, the seek filter, and encoding.
core/readParams.js Request → filters, sort, page window. Pure: no database, no response, no this. Shared by GET and QUERY.
core/search.js Search terms, escaped, including across referenced models.
core/write.js Body → payload: the field policy, then your validator.
core/dataAccess.js Every Mongoose call, with maxLimit, maxTimeMS, lean and onGet already applied.
core/respond.js The response envelope, so no endpoint can invent a fifth shape.

The split is why GET / and QUERY / cannot drift apart: they differ only in which readParams function turns the request into parameters, and agree on everything after that.

Add routes to a generated router#

A generated router is an ordinary Express router. Mount your own routes on the same path — declare the more specific ones first so they aren't captured by /:id.

const extras = express.Router();
extras.get('/featured', listFeatured);      // would otherwise hit /:id

app.use('/api/products', extras);
app.use('/api/products', createRouter({ model: Product }));

Uploads without CRUD#

import { fileUploadMiddleware } from 'express-controller-sets';

const upload = (req, res, next) => fileUploadMiddleware(req, res, next, {
  uploadPath: 'invoices/',
  fields: [{ name: 'invoice', maxCount: 1 }],
  allowedMimeTypes: ['application/pdf'],
  maxFileSize: 2 * 1024 * 1024,
});

app.post('/api/invoices', requireAuth, upload, (req, res) => {
  res.json({ url: req.body.invoice });   // already uploaded and validated
});
TypeScript

Type declarations ship with the package. Nothing to install.

import express from 'express';
import { createRouter, errorHandler, type RouterOptions } from 'express-controller-sets';
import Product, { type IProduct } from './models/Product.js';

const options: RouterOptions<IProduct> = {
  model: Product,
  orderBy: '-createdAt',
  query: ['category'],
  allowedFields: ['name', 'price'],
  onGet: async (req, res) => ({ populates: 'category', selects: 'name price' }),
};

const app = express();
app.use('/api/products', createRouter(options));
app.use(errorHandler);

Exported types you'll reach for: ControllerOptions, RouterOptions, RouterS3Options, UploadOptions, UploadField, OnGetFn, OnGetResult, FieldPolicy, ImageOptimizationLevel and Logger — plus QueryRequestBody, FilterCondition, FilterOperators and FilterScalar for the QUERY body, and ValidateFn, ValidateContext, ValidatePolicy, WriteOperation, CountStrategy and Pagination for validation and paging.

Typing the body on the client side keeps a filter honest before it is ever sent:

import type { QueryRequestBody } from 'express-controller-sets';

const body: QueryRequestBody = {
  filter: { price: { gte: 50, lte: 250 }, tag: ['sale'] },
  sort: ['-price', 'name'],
  pageSize: 20,
};

await fetch('/api/products', {
  method: 'QUERY',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(body),
});

Types don't validate field names. allowedFields is string[], so a typo — 'pirce' — compiles happily and silently drops the real field at runtime. If a field refuses to save, check the spelling in your allowlist first.

Recipe: extra endpoints next to a generated router

A generated router is an ordinary Express router. Mount your own routes on the same path — before it, so they win.

const products = express.Router();

products.get('/stats', async (req, res) => {
  const [row] = await Product.aggregate([{ $group: { _id: null, avg: { $avg: '$price' }, n: { $sum: 1 } } }]);
  res.json({ success: true, data: row ?? { avg: 0, n: 0 } });
});

products.use(createRouter({ model: Product, allowedFields: [] }));

app.use('/api/products', products);    // GET /api/products/stats, plus the six generated routes

To reuse the generated behaviour under a different verb or path, call the handlers directly — see Custom routes.
